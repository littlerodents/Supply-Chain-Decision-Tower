## 自我 grilling

### R1

❓ **Q1：「8 cells 撑得起一个 skill 的厚度吗？」**
➡️ 撑不起。MMM 的价值在完整流程（清洗→adstock→拟合→优化→敏感度），notebook 只有核心。补全=自造大量内容，**偏离「FDE 案例转化」初衷**（转化≠重写）。

❓ **Q2：「evals 客观性？」**
➡️ 弱——贝叶斯拟合质量无唯一真值。可行路径只有「合成数据上恢复真实系数」（要现造合成场景=额外工作量+口径争议风险）。

❓ **Q3：「撞车检查——MMM 开源生态成熟，skill 化的差异化在哪？」**
➡️ 难答。Google Meridian、Meta Robyn 都是开源 MMM——我们的 skill 相对它们只是薄包装。技术深度 25% 的评委大概率知道这些工具，原创性会被质疑。

### R2

❓ **Q4：「pymc/bayes 工具链在 ARM64（租机）上的坑？」**
➡️ **UNPROVEN**——pymc 依赖链（theano/pytensor 编译）在 ARM 上历史坑多。若选它，SPEC 阶段必须先跑通安装冒烟，否则冻结前夜翻车是剧本级风险。

❓ **Q5：「agent 编排价值在哪？」**
➡️ 弱——MMM 跑一次几小时（贝叶斯拟合），不构成「问一句出建议」的交互形态。agent 只是批处理壳，同 ② 的弱点但更重。

## 残留风险（明示）

1. 厚度不足 → 需大量自造内容，偏离方向
2. evals 客观性最弱
3. ARM64 依赖链 UNPROVEN
4. 撞 Robyn/Meridian 生态，原创性受质疑
