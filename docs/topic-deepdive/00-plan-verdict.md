## 四条攻击线的最狠一刀与回答

### A · 赛题适配线

❓ **Q1（最狠）：「整个 skill 在笔记本上也能跑——LLM 在云上、数据 <1MB、cuDF 被你自己降级了。DGX Spark 到底干了什么不可替代的事？平台适配 15% 凭什么给？」**
➡️ 成立性抢救：① OpenClaw gateway + skill 运行时**跑在 Spark**（agent 层吃本地算力）② **备脑 120B 只能跑在这种统一内存机器上**（87GB 模型，笔记本物理不可行——这本身就是不可替代性的实物证据）③ 整演示栈部署于 Spark。评分原文是「**合理运用**」不是「榨干算力」。
**修正案 R1：换脑环节（3.7-flash ↔ 本地 120B）从可选项升为必选项——它是平台适配分的承重墙。**且排演示最后一幕（120B 上场时其他进程最少，OOM 翻车不毁主线）。

❓ Q2：「没人真做过供应链 FDE，行业可信度？」
➡️ 赛题不要求行业出身。README **透明引用**（基于 ikatsov/tensor-house 的 Apache-2.0 案例转化）——诚实引用是加分项：把已验证的落地经验标准化复制，本来就是 FDE 工作的本质，我们做 FDE 的事而不假装行业专家。

❓ Q3：「实用性证据只有 MIT 95% + SaaS 形态存在，够吗？」
➡️ 半接受。缺「具体客户」微叙事——缓解：演示给一个典型客户（区域零售 3 仓 50 SKU），README 引 FDE 书 300 门店场景。证据是「行业的」不是「某家的」，明示接受。

### B · 工期工程线

❓ **Q4：「processors 覆盖面 UNPROVEN 是唯一 P0——明天才翻车怎么办？」**
➡️ **修正案 R3：N1 提前到锁题后第一件事（20 分钟内克隆实测）**，把翻车发现窗口压到最早；② 接棒条件已写死（topic-deepdive/02），其数据自给性已实测。

❓ Q5：「9/25-26 两天装下 N3-N5，加了个 Streamlit 塔台，够吗？」
➡️ 拆解：N3 skill 主链≈repro-pack D2 的量（1 天）；N5 上机=D3 剧本照抄（半天）；**新增风险位只有 Streamlit 适配**（原项目环境依赖 UNPROVEN）。
**修正案 R2：Streamlit 降级为可牺牲项**——适配超 4 小时即降级为「原样 demo 录屏」，承重墙是 OpenClaw 对话。塔台是演示项，不是功能项。

❓ Q6：「120B+OpenClaw+Streamlit 同跑，OOM 重启（横幅警告）？」
➡️ 实测余量 ~25GB+；演示脚本按序加载（主线用 3.7，换脑最后一幕才上 120B）。风险可控，方案见 R1。

### C · 团队过程线

❓ Q7：「evals（核心件）分给了兜底成员 AB？」
➡️ 半接受：evals runner 有 repro-pack 验证过的现成方法论，T 卡住我即接；BOARD 分工可调。**承重墙全在 O 线是设计意图：单点可活，多人加速。**

❓ Q8：「上次 P 图合影的坑，还有类似的雷吗？」
➡️ **修正案 R5：发布排雷清单进 README checklist**——① 征文/B 站视频按平台规范标注 AI 生成（赛规原文）② 转化物保留 Apache-2.0 + 案例署名 ③ key 零提交（已验证）④ 合影（已留痕，owner 决定）⑤ 500 字 README 结构逐条对赛规。

### D · 战略线（真正最狠的一刀）

❓ **Q9：「三天改两次方向，评委翻 git 历史看到个半途而废的 repro-pack——团队决策不稳定？」**
➡️ 恰恰相反：**这是征文的全部素材**（十日谈 5% 的评分点）。repro-pack 死于 owner 的真实洞察（接入优先时代），FDE 转向源于会议共识+证据搜索——ISA.md 里躺着完整决策链。评委看到的不是摇摆，是「一套方法论（evals/负例/换脑/台账）在两个方向被验证后继承」。残留：新方向零代码落地（N1 未开）——所以 N1 是第一优先。
