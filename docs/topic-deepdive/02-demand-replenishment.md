# 候选档案 ② · 需求预测→补货决策 skill（源：demand-multivariate-glm × single-echelon-sQ-RS）

> 2026-09-24 · grilling 结案版。

## 选择理由（证据）

| 理由 | 证据 |
|---|---|
| 零数据风险 | 实测：glm notebook read_csv=0、外部下载=0、合成数据=5 处；sQ-RS 同（合成=2）——全自给 |
| evals 最硬 | MAPE/服务水平/补货量是数学唯一解，负例（库存充足→不补）天然存在 |
| 实用性叙事直白 | 补货拍脑袋→数据进、补货单出；FDE 书「300 门店 Excel」场景可直接套用 |
| 规模可控 | glm 14 cells + sQ-RS 20 cells，数小时可吃透 |

## 自我 grilling

### R1

❓ **Q1：「串两本 notebook = 两倍工作量？」**
➡️ 真。缓解：砍 DeepAR/Prophet 全家，只留 glm→sQ-RS 一条链，预测层做「够用版」，重心压在决策链。工作量比 ① 大（① 有现成 processors，② 要自己拼链）。

❓ **Q2：「agent 在哪？这不是一条分析管道吗？」**
➡️ 半接受——skill 形态是「销售 CSV 进→补货单出」的批处理管道，对话性弱于 ①（① 是自然语言控制塔，一句「3 号仓 A 商品该补多少」就是完整 demo）。skill 触发场景 =「帮我生成补货计划」，演示形态吃亏（评分：演示 10%）。

❓ **Q3：「需求预测是数据科学课经典题材，评委见太多了？」**
➡️ 真——新颖性是四候选最弱项。靠「FDE 案例」框住才及格，否则像课程作业搬进 skill 壳。

### R2

❓ **Q4：「合成数据讲不出真痛点，实用性 25% 的证据链？」**
➡️ 缺口真实存在。缓解：FDE 书叙事（门店 Excel 场景）+ 扩一个公开零售数据集（如 Retail Rocket 类）——但这是**新增工作量**，工期方差变差。

❓ **Q5：「撞车检查？」**
➡️ NVIDIA catalog 的 cuOpt/VSS 均非需求预测；社区 demand-forecast 类 skill 存在感低。撞车风险低，但新颖性也低（与 Q3 同根）。

## 残留风险（明示）

1. 串链工作量大于 ①（无现成 processors）
2. agent 性/对话性弱 → 演示吃亏
3. 真实数据叙事需要额外工作量补

## 结案声明

无未答之问。**推荐位次：2**——工期安全垫最厚、evals 最硬，但叙事与演示平庸。仅当 ① 的 processors 实测翻车（克隆后覆盖面不足）时启用，届时 ② 接棒为主候选。
