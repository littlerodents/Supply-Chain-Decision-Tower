## 4. 功能与架构对照

实现逻辑必须能沿着 `输入范围 → CSV库存 → 合成预测 → gap=库存-需求 → 分支 → 工具事实/Agent原答 → 独立核验 → 页面` 逐步解释：

- gap≥0：只输出无需补货和余量（件）。gap<0：逐个供应商取真实发货地与运费，比 `unit_cost+shipping_cost`，推荐最低总单价，订量=-gap，总成本按分核算。不额外引入业务中未定义的安全库存或真实订单。
- 图表、面板指标、Agent核算使用同一输入快照与数据哈希。样本当前3SKU/3城市/5库存行/4供应商行；预测是合成序列且当前与仓库无关，不宣传真实预测精度。
- 当前后端是Streamlit进程内Python工具+另一路OpenClaw，不是已有HTTP业务API；实时适配器的字段和错误合同见PRD §5。前后端不必拆成两种框架，但页面点提交必须能追到相同request_id的真实工具执行。
