# 新前端对接规格书 · FIELDWORK 风格供应链控制塔（v1.0，2026-09-27）

> 给前端工程师：你的新前端**不需要也不应该碰 Streamlit**。所有能力通过本机 HTTP JSON API（`:8765`）获取，契约如下，全部端点已实测（示例即真实返回）。后端已冻结，界面对接零风险。
> 原型映射：设计稿为编辑风「FIELDWORK 供应链控制塔」——hero（品名+大数字库存）+ 左侧「发起分析」表单卡（工具核算/Agent 决策双模式、SKU/仓库/周数/业务问句、开始分析）+ 右侧结果面板（库存卡、下一步引导、库存一览）。

## 0. 接入方式

- API 基址：`http://127.0.0.1:8765`（开发时在 Mac 上开隧道：`ssh -p <SSH端口> -N -L 8765:127.0.0.1:8765 sparker@<你的DGX-SSH地址>`，然后前端指向 `http://localhost:8765`）
- 已开 CORS（`Access-Control-Allow-Origin: *`），本地开发任意端口直连
- 服务已在 DGX 常驻（`panel/api_server.py`，日志 `~/api.log`，重启：`kill $(cat ~/api.pid) && nohup python3 ~/.openclaw/workspace/skills/supply-chain-control-tower/panel/api_server.py >~/api.log 2>&1 & echo $! > ~/api.pid`）
- 所有响应 `application/json; charset=utf-8`；错误统一 `{"error":{"type","message"}}` + 4xx/5xx

## 1. 端点总览（组件 → API 映射）

| 设计稿组件 | 端点 | 说明 |
|---|---|---|
| SKU/仓库下拉 | `GET /api/products` | 含双语 display 与各 SKU 有记录的仓 locations（仓库选项只从这里取，避免无记录组合） |
| hero 大数字/库存一览 | `GET /api/inventory` | 64 条全量，含 display |
| 工具核算模式（秒出） | `GET /api/gap?sku&location&weeks` + `GET /api/suppliers?sku&location` | gap 缺口/record_exists；board 比价含运费与 flip 标记 |
| Agent 决策模式（60-120s） | `POST /api/decision` → 轮询 `GET /api/decision/{job_id}` | 双智能体流水线，返回决策包+决策单文本 |
| 下一步引导卡 | 决策包里的 `overall` / `slip_text` | PASS→"进入采购审批"，NO_RECORD_TRUTHFUL→"该仓无此品" |
| 巡检/排行视图（可选扩展） | `GET /api/scan?weeks` 或 `/api/scan/latest` | 64 组合秒级 |
| 上传自己的表（可选扩展） | `POST /api/upload/preview` → `/api/upload/scan` | AI 建议映射可由前端另调 Agent 或让用户手选，mapping 字段名见 preview 返回 |

## 2. 端点契约与真实示例

### 2.1 `GET /api/health`
```json
{"ok":true,"service":"supply-chain-tower-api","port":8765,
 "model":"nemotron-3-super:120b-a12b + 适配器（本地主力）/ step-3.7-flash（云端备用）",
 "data":{"skus":48,"inventory_rows":64,"supplier_rows":75}}
```

### 2.2 `GET /api/products`
```json
[{"sku":13001,"brand":"Colombian Coffee","display":"13001 哥伦比亚（Colombian Coffee）",
  "locations":["San Francisco","Seattle"]}, ...]
```
（注：display 的中文名当前覆盖核心 6 品类，其余为英文原名——前端原样展示即可。）

### 2.3 `GET /api/gap?sku=13001&location=San%20Francisco&weeks=12`
```json
{"sku":13001,"location":"San Francisco","weeks":12,"record_exists":true,
 "current_stock":30,"forecast_demand":3298,"gap_stock_minus_demand":-3268,
 "note":"gap<0=短缺需补货；gap>=0=充足无需补货"}
```
**前端必守**：`record_exists=false` 时如实显示"该仓无此品库存记录"（note 字段有中文说明），**不得**把库存 0 当真实库存渲染成补货建议。gap≥0 显示"无需补货·余量 N 件"。

### 2.4 `GET /api/suppliers?sku=14001&location=San%20Francisco`
```json
{"board":[
  {"supplier":"Golden Gate Roasters","location":"San Francisco","unit_cost":19.9,"shipping":2.0,"total_unit":21.9},
  {"supplier":"Budget Beans Co.","location":"Los Angeles","unit_cost":15.5,"shipping":7.0,"total_unit":22.5}],
 "flip":true}
```
board 已按 `total_unit` 升序（第一个即推荐）；`flip:true` 建议高亮"运费翻转：单价最低者并非总单价最低"。建议订量 = `-gap`；总成本 = 订量 × total_unit（首个）。

### 2.5 `POST /api/decision`（异步 job）
请求：`{"question":"San Francisco 仓库 SKU 13001 未来 12 周够卖吗？需要补货吗？","with_audit":true}`
```json
{"job_id":"5d6e79f4c9","status":"RUNNING","poll":"/api/decision/5d6e79f4c9","expected_seconds":"60-120"}
```
轮询 `GET /api/decision/{job_id}`（建议 3s 间隔，前端展示已等待秒数）：
```json
{"status":"SUCCEEDED","finished_at":"20:31:12","result":{
  "question":"...","overall":"PASS",
  "decision_agent":{"session":"pi-dgx-api-xxx","model":"stepfun/step-3.7-flash","duration_ms":23400,
                    "tool_summary":{"calls":4,"failures":0},"final_text":"模型原话...",
                    "decision_json":{"decision":"REORDER","sku":13001,"order_qty":3268,
                                     "supplier":"Nature Source Coffee","unit_cost":34.5,
                                     "shipping_cost":2.0,"total_cost":119282.0,...}},
  "independent_verification":{"verdict":"PASS","checks":["订量 3268/3268:OK",...]},
  "audit_agent":{"session":"pi-dgx-api-yyy","verdict":"PASS","tool_summary":{...},"final_text":"审计原话..."},
  "slip_text":"补货决策单 · ...\n...\n状态：✅ 双重验证通过，可进入采购审批"}}
```
**状态机**：`RUNNING → SUCCEEDED | FAILED`（FAILED 带 error）。`overall` 取值：`PASS`（双绿）/ `FAIL` / `NO_RECORD_TRUTHFUL`（如实拒答，展示为正常态不是错误）。**提交后禁用按钮直到终态；失败不自动重试**。

### 2.6 `GET /api/scan?weeks=12`（或 `/api/scan/latest`）
返回巡检报告（结构同 2.8 的 report）：`combos/shortage_count/ample_count/flip_count/total_reorder_cost/shortages[]/ample[]`，`shortages` 按 `total_cost` 降序，字段含 sku/brand/location/stock/demand/gap/order_qty/supplier/unit_cost/shipping/total_unit/total_cost/flip。首次调用约 2-3 秒。

### 2.7 `POST /api/upload/preview`
`{"file_b64":"...","filename":"工厂库存样例.csv"}` →
```json
{"rows":9,"columns":["料号","品名","仓库","当前库存","周均需求","供应商","供应商城市","含税单价"],
 "sample":[{...3 行...}],"mapping_fields":{"sku":"SKU/料号/品号（必填，唯一编号）",...}}
```
前端做映射选择 UI（AI 建议可后置，先人工下拉）。

### 2.8 `POST /api/upload/scan`
`{"file_b64":"...","filename":"x.csv","mapping":{"sku":"料号","location":"仓库","quantity":"当前库存","weekly_demand":"周均需求","supplier":"供应商","supplier_city":"供应商城市","unit_cost":"含税单价","product_name":"品名"},"default_weekly_demand":100,"weeks":12}`
→ `{"notes":["降级说明..."],"report":{...同 2.6...}}`；校验失败 → 422 `{"error":{"type":"ValidationError","messages":["必填字段未映射：..."]}}`。

## 3. 演示动线（对应设计稿 01—03 步骤感）

1. hero 默认品（如哥伦比亚 13001@SF）→ `/api/gap` 渲染大数字卡（库存 30 / 12 周需求 3298 / 缺口 3268）
2. 左卡切「Agent 决策」→ 预填业务问句 → 开始分析 → 轮询 job → 右面板出：决策八字段 + 独立核算徽章 + 审计徽章 + `slip_text`（提供"下载决策单 .txt"按钮，前端 Blob 即可）
3. 「下一步」引导卡：overall=PASS → "可进入采购审批"；展示会话号以示可追责

## 4. 红线（与评审 PRD 一致）

- 只读：本 API 无任何写业务数据的端点
- 不下发任何凭据；决策在服务端经 openclaw 默认路由执行
- `record_exists=false`、`overall=FAIL/NO_RECORD_TRUTHFUL` 必须如实呈现，禁止把错误修饰成成功
- 超时约定：决策 150s 服务端硬超时；前端 180s 前保持等待态
