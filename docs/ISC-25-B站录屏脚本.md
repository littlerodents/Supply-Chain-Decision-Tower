## 逐镜台词与操作

### 镜 1 · 标题卡（0:00-0:20）

画面：黑底白字标题卡（可用表单内容包里的项目名+一句话介绍）。

> 台词：供应链控制塔——一个会说"不"的补货决策智能体，跑在 DGX Spark 上。它把运营者的一句话，变成一份带工具证据的补货决策单；库存够的时候，它敢直接告诉你：不用补。

### 镜 2 · 架构与平台（0:20-0:50）

画面 A（10s）：一页架构图（三栏：自然语言入口 → OpenClaw 网关+Skill SOP+七只读工具（本地） → 决策脑 StepFun step-3.7-flash；底部标注"库存数据/面板/开源模型 120B+30B 全在 DGX Spark 本地"）。

> 台词：架构是混合的。库存数据、七个只读工具、Streamlit 面板、还有两颗开源模型，全部在 DGX Spark 本地，敏感数据不出机器；决策脑用的是 StepFun 阶跃星辰 step-3.7-flash——为什么这么分工，一会儿用数据回答。

画面 B（20s）：终端依次跑两条命令（提前开好终端，字号调大）：

```bash
nvidia-smi
~/ollama/bin/ollama list
```

> 台词：这台是 DGX Spark，GB10 芯片，119G 统一内存，CUDA 13。本地这颗 86G 的 120B 模型就整个躺在内存里，随时可切——评测里它会出场。

### 镜 3 · 正例 live（0:50-1:50）★核心镜头

画面：终端。逐字敲入（或粘贴）：

```bash
export PATH=$HOME/node26/bin:$PATH
openclaw agent --session-id pi-dgx-demo-take1 \
  --message "San Francisco 仓库 SKU 13001 未来 12 周够卖吗？需要补货吗？" --json
```

等待约 15 秒（可剪辑加速，但保留工具调用可见部分）。

> 台词（边等边念）：注意，回答里每个数字都必须有工具证据——这是写进 SOP 的红线：没有工具输出，就没有回答。它现在正在查库存、算缺口、比供应商和运费。

结果出来后，把 JSON 关键字段指给镜头看（可用鼠标选中高亮）：

> 台词：看这个决策——传统缺口分析说要补 3268 件，但我们的 ROP 优化算法说：只需补 359 件。为什么？因为安全库存分析显示当前需求波动 σ=35，95% 服务水平下安全库存只需 57 件。我们不是简单补全缺口，而是科学计算最优订量——减少过度库存 89%。供应商 Nature Source Coffee，单价 34.5 加运费 2 块。全部来自工具直算，不是模型猜的。

### 镜 4 · 负例 live（1:50-2:20）

```bash
openclaw agent --session-id pi-dgx-demo-take2 \
  --message "Seattle 仓库 SKU 13001 未来 1 周够卖吗？需要补货吗？" --json
```

> 台词：换一个仓库，只看一周。库存 300，需求 200，盈余 100——看最后一行。

高亮末行 `NO_REORDER:100`：

> 台词：NO_REORDER，盈余 100。它没有"建议适度补货"，没有给供应商，什么建议都没有——库存够就是够。通用大模型总倾向于显得有用，这一行是我们专门设计出来的信任时刻。

### 镜 5 · 控制面板（主界面=新前端 FIELDWORK，备份=Streamlit:8501）

> 录屏主界面改为新前端：`http://192.168.11.205:5173`（FIELDWORK 编辑风）。左表单（工具核算/Agent 决策双模式）→ 右结果面板（hero 大数字/下一步引导/库存一览）。工具模式秒回；Agent 模式轮询 60-120 秒出决策+核验徽章。Streamlit:8501 保留为备份机位（四 Tab 版）。

### 镜 5B · 备份素材：Streamlit 面板（每日巡检 → 工具证据 → 实时 Agent，2:20-3:20）

画面 A（25s）**产品开场**：浏览器 `http://<DGX-IP>:8501` 第一个 Tab「📋 每日巡检」。点"🔄 生成巡检报告"，两秒出结果：64 个组合、25 个短缺、2 个运费翻转、建议采购总额 217 万美元。滚动短缺排行表。

> 台词：这才是它作为产品的样子——供应链经理的早晨不是挨个问问题，是点一次巡检：64 个 SKU×仓库组合全部扫完，25 个短缺按采购金额排好序，运费翻转陷阱直接标星。工具直算，秒级，零大模型成本。

画面 B（15s）：切「🧮 工具证据」Tab，选 14001@San Francisco 展示运费翻转卡与无记录防护（13001@Portland）。

> 台词：每一个数字都能追到工具直算的证据；没库存记录的组合只说无记录，不把未知当零库存。

画面 C（25s）：回到巡检页选一个 ⭐ 翻转组合 → 点"填入问句" → 切「🤖 实时 Agent」提交（勾审计）。出结果指三块：原答/独立核算/审计判定。

> 台词：对例外开口追问——模型给单，面板独立核算，第二个智能体审计盖章。从巡检到可签字的决策单，一个闭环。

### 镜 5.5 · 上传自己的数据（3:20-3:40，产品收尾镜头）

画面：切「📤 上传我的数据」Tab，拖入 `~/isc-submission-20260927/素材/工厂库存样例.csv`（紧固件厂 9 行：料号/仓库/库存/周需求/供应商/城市/单价）。点「🤖 AI 映射建议」等约 20 秒——下拉框自动预选；点「✅ 确认映射并校验」→「🚀 在我的数据上巡检」。

> 台词：最后一件事——这不是只能跑我们演示数据的玩具。把你工厂的表拖进来，AI 读懂你的列名，你确认一下，十秒后就是你自己的短缺排行和补货单。AI 建议、人确认、工具算数——这套信任架构对任何数据都成立。

画面：A/B 结论卡（三行大字），下半屏（或右半屏）放**团队合照** `~/isc-submission-20260927/素材/team.jpg`（三人在夜晚街头的合照，裁成横幅铺在结论卡下方）：

> 画面收尾：合照上叠一行小字「我们是 ___ 队」+ 队名/成员名（owner 补），淡出。

## 录制前自检（5 分钟）

1. `systemctl --user is-active openclaw-gateway` 必须是 `active`。
2. 空跑一条 take 确认网关通：用 take0 跑正例（别占用 take1/take2）。
3. 面板 `http://<DGX-IP>:8501` 提前打开加载完，**两个 Tab 各点一遍**：工具证据页选一次 14001@SF；实时页空提交一次正例（约 40 秒，确认出 PASS 三件套：原答/独立核算/审计 JSON）。视觉有问题随时找 DGX 会话修（只动 panel/app.py，后端已冻结）。
4. 终端字号调大（录屏可读），背景干净，敲命令慢一点。
5. 证据兜底：`/home/sparker/isc-submission-20260927/素材/pi-dgx-final27-*.json`（3/3 原始输出）和 `nvidia-smi.txt`/`ollama-list.txt` 都在——**若 live 翻车，切录屏展示这三个 JSON 文件并照念台词，照样成立**。
