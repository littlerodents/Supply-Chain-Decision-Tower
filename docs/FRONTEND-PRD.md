# 前端 PRD · 供应链控制塔评审演示面（v0.2 · 实施验收稿）

> 2026-09-27 · **这是目标规格，不是已上线功能声明。** 对应评审「项目完整性 20%」中的前端、前后端闭环与可演示性；实施须遵守 9/26 晚冻结基线及另行批准的运行时改动。产品主线仍是可安装的 Skill 与自然问句，面板不能取代 OpenClaw 入口验收。上层验收见 [项目完整性 SPEC](REVIEW-COMPLETENESS-SPEC.md)。本文不要求重建技术栈，优先复用现有 Streamlit 与工具层；新增实时集成需另行授权。

## 1. 可观察结果与现状

评委在不看代码的 3 分钟里，能分清**工具直算的业务事实**和**Agent 的最终决定**：正例看到 SKU13001@San Francisco/12周的 30 库存、3298 需求、补 3268、Nature Source Coffee、119282；负例看到 SKU13001@Seattle/1周的 300/200/+100、**不补货**。任何缺数、工具错误或模型违约均明确显示「未通过」，不能自动修饰成成功答复。

- **现有** `skills/supply-chain-control-tower/panel/app.py`：Streamlit :8501 的只读证据面板，SKU/仓库/周数控件、缺口、库存、预测曲线和两张 CSV 表；直接调用确定性工具，不连接 Agent。2026-09-27 01:07 CST 远端文件 SHA256 与本地一致、Gateway 用户服务 active、面板 HTTP 200；**HTTP 200 不证明交互或 Agent 集成已验收**。
- **Agent 另一路（仅已证基线）**：DGX OpenClaw 经显式 `--model stepfun/step-3.7-flash` 的历史两正一负通过；最近留存的默认模型核查是 Ollama/Nemotron，非本轮新鲜运行态核查。三份原始 JSON 在被忽略的 `evidence/2026-09-26-iris-preflight/step-acceptance/`。模型终答的 `tool_trace` 是声明，不等于逐次工具参数/结果轨迹。
- **当前产品约束**：`ISA.md` 记录 owner「入口不想用云端」；本地 Nemotron 三题 1/3（正例 0/2）、Qwen 两题 0/2，**无已通过本地正例的实时入口**。云端 StepFun 仅作已证对照，不得默认为待上线前端主脑。是否改选云端是 owner 的单独决策，本 PRD 不代选。
- **未实现**：浏览器内提问→Gateway→结果与工具证据同屏；浏览器密钥隔离、错误态、证据回放。不能把当前面板称为完整 Agent 聊天前端。

## 2. 用户与演示场景

- 供应链经理：通过**自然问句**理解补/不补、量价和依据；可切换 SKU、仓库、周数探索只读数据，不会触发真实下单。
- 评委：在 1080p 录屏或受控现场，识别当前模式、模型、数据来源、成功/失败与响应时间；独立重跑时不会把历史回放误当实时会话。
- 演示者：在模型/API 不可用时能展示可信的确定性面板及明确标注的历史回放，**不能称真入口本轮通过**。

## 3. 模式与最小页面

| 模式 | 界面必须显示 | 准入条件 |
|---|---|---|
| **工具证据**（基础面板已存在，防护待补） | SKU、仓库、1–26 周；库存、需求、gap（件）；图题/点数与所选周期一致；样本来源及读取时间；库存/供应商只读表 | 本地工具和样本 CSV 可读；不声称 Agent 已作答。现有图题写 52 周但实际截取点数，本项尚未通过 |
| **实时 Agent**（拟议，当前不可宣称可用） | 自然问句输入、**实际所选模型/云或本地**标识、运行中/超时/失败/通过态；最终原文和**独立核算栏**同屏 | 先满足 owner 本地入口约束和正负例严格入口验收，再建安全服务端适配器与真实工具事件；不得在浏览器保存/下发 API key |
| **证据回放**（拟议） | 回放水印、会话时间、脱敏来源引用；同样展示成功与失败样本 | 只读加载 owner 审核后的脱敏证物，不请求模型、不伪装实时 |

### 3.1 单页信息结构

```text
供应链控制塔 | 工具证据 / 实时 Agent / 证据回放 | 模型位置与就绪状态
本地样本 · 非实时库存 · 合成预测 · 数据版本 / 读取时间
┌ 问题与范围（约 1/3） ────────┬ 结果与依据（约 2/3） ────────────┐
│ 可编辑问句 / 场景快捷填入      │ 短缺 / 充足 / 未通过（文字+图标）  │
│ SKU、仓库、周数              │ 库存、需求、gap；补货量、总金额    │
│ 范围确认 / 提交 / 运行状态     │ Agent 原答 | 独立核算 | 差异       │
└───────────────────────────┴───────────────────────────────┘
所选周期需求图 | 来源说明
库存明细 / 供应商原始数据（不是推荐） | 证据抽屉（默认折叠）
```

- 工具模式只提供参数控件，不出现伪聊天框；实时模式未就绪时输入/提交禁用，旁边解释原因。模式切换不触发推理，也不自动切模型。
- 自然问句是实时模式主输入；场景按钮只填入可编辑问题，不自动发送。参数区域用于确认解析范围；它与问句不一致时进入 `NEEDS_INPUT`，禁止默默以控件覆盖问句。参数按意图检查：补货决策需SKU/仓库/周期；库存或供应商查询仅要求各自筛选条件，不能强迫它们填决策周期。工具模式允许显式标注的默认场景（12 周），不把该默认值灌入缺周期的自然问句。
- 正例主卡展示「建议补货 3268 件 / USD 119,282.00」，负例展示「无需补货 / 余量 100 件」。原始 JSON/末行文本保留在证据区，金额不得简写为 119K 代替可核验值；全局供应商表是原始数据，不是负例推荐卡。
- 优先 1920×1080 演示；1366×768 下允许纵向滚动、不截断主结论或提交按钮。正文≥16px；红/绿同时配文字/图标；控件有可读标签，Tab 可按输入→提交→证据顺序操作。不新增移动端、账户管理、订单执行或复杂导航。

### 3.2 三条用户流程

1. **工具事实**：选已有库存组合→确认周期→显示工具核算和同周期曲线→展开原始数据。无记录立即显示「缺数据」，不产生补货结论。
2. **实时决策（待实现）**：模型/适配器就绪→填入或输入自然问句→确认范围→提交→等待→同时展示原答及核算→合同通过才显示成功。状态查询只给工具表/图，不强迫输出补货 JSON；天气等无关问句标「不属于本 Skill」，业务工具调用数为 0。
3. **历史回放（待实现）**：手动选择脱敏样本→持续显示「历史回放」、原会话时间与模型位置→看成功或失败原答。不得显示实时计时动画、触发模型或借当前时间伪装新回答。

### 3.3 状态与并发合同（拟议）

| 状态 | 用户所见与下一步 | 不允许发生 |
|---|---|---|
| `NOT_READY` | 入口/数据/模型未就绪，提交禁用，给具体原因；仍可查看工具或回放模式 | 自动切云端或自动安装/重启服务 |
| `IDLE / NEEDS_INPUT` | 待输入或指出缺少/冲突的 SKU、仓库、周期；用户修正后再提交 | 猜周期、接受 0/负数/小数/超过26周 |
| `RUNNING` | 单会话仅一个活动 request_id；显示已耗时、实际阶段（仅事件已观测时），禁重复提交 | 假进度、前端每次重绘重复请求、先展示旧结果为新答 |
| `SUCCEEDED` | 显示模式、范围、数据版本和核验通过的结论；可展开工具事件 | 仅凭 HTTP 200 或模型自报判成功 |
| `FAILED / TIMED_OUT` | 「未通过/未出决策」+ 可读原因；保留原答与差异供审计；仅手动重试 | 静默修答案、自动重试烧模型、失败却展示绿色卡片 |
| `STALE / REPLAY` | 修改范围/模式后旧结果打过期标签；回放始终带历史水印 | 迟到响应覆盖新请求；刷新后把历史结果冒充运行中 |

演示目标 30 秒内完成；拟议等待上限 60 秒后转 `TIMED_OUT`，二者均是待测产品目标。超时不等于后端已取消：若无法确认停止，显示「后台状态未知」并阻止重复提交，不能用取消按钮重启或杀 Gateway。刷新丢失 request_id 时回到未知/未就绪，不能盲目补发。服务端或组件内部调用均须遵守该行为合同。

### 3.4 最小功能优先级

- **P0-A 工具面修实**：同周期图、无记录防护、真实供应商发货地与运费、模式/单位/样本标识、负例卡、错误态。可在不接模型的前提下单独验收；不等于完整 Agent 前端。
- **P0-B 完整实时闭环**：获准且通过验收的本地模型入口、服务端适配、自然问句、原答/核算分离、真实工具事件、请求隔离；这是声明前后端完整的必要条件，当前未实现。
- **P1 辅助演示**：经过脱敏审核的证据回放、全52周图切换；即使未做也不能用伪实时效果替代。是否走原 SPEC 的 R2 降级记录，由项目决策单列，不能把 P0-B 勾成已完成。

## 4. 关键交互与规则

1. **参数与数据**：自然问句缺周期先提示补齐，不默认 12 周；SKU/仓库只能选样本里有定义的组合，或明确提示「无库存记录」。当前样本为 **3 SKU、3 城市、5 条库存行、4 条供应商行**，不是完整3×3库存矩阵。`stock_demand_difference` 对查无记录返回 0，UI **不得将未知库存伪装为真实零库存并建议补货**；服务端先检查记录存在性，直接传入非法参数也要拒绝。预测必须标为合成，数列目前不随仓库变化，日期轴按运行日生成；旧回放使用原采样日期，不能拿新日期覆盖。P0 图题=所选 N 周、点数=N；当前标题52周与截取点数不符，应修而非宣传已实现。供应商来源按查询结果显示，Seattle→目标仓的参考价不能冒充所有 SKU 的真实路线（如 SKU11001 供应商在 San Francisco）。
2. **正例**：最终回复的末个 JSON 代码块须含 decision/order_qty/supplier/unit_cost/shipping_cost/total_cost/rationale/tool_trace，且 `decision=REORDER`；数值与**独立工具核算**一致，本题须 3268、Nature Source Coffee、119282。原答与核算不一致时展示差异并标失败，不悄悄替模型改答；只有实际工具调用轨迹能证明工具执行，`tool_trace` 仅作为模型自述。
3. **负例**：库存-需求 gap≥0 时，末行须独占纯文本 `NO_REORDER:<gap>`，gap 为**非负整数件数，不是周数**；本题 `NO_REORDER:100`，恰好充足为 `NO_REORDER:0`。成功结果区不得有订量/供应商推荐或补货建议。若模型误触，整次标 FAIL，错误原答在审计区可见，不能靠隐藏文字使验收通过；不因包含 NO_REORDER 就判过。
4. **错误态**：数据缺失、工具报错、鉴权失败、Gateway 不可用、超时、补货正例无 JSON/错算术，均显示明确原因与「未出决策」；禁止虚构数字、重复自动提交或把旧结果显示为新结果。单次响应的演示目标 ≤30 秒只是待测目标；7.7–12.9 秒仅是云端 StepFun 三样本，**不能迁移为本地脑的 SLO**。
5. **安全**：只读、不下单、不写库存；不在网页、URL、日志、截图、前端包或回放里出现 StepFun/SSH 密钥和未经脱敏的原始会话；不暴露公网端点。任何 Gateway 配置、服务重启及公开部署需单独授权。

## 5. 接缝与验收（实现前的硬门）

现状是 `浏览器 → Streamlit服务端 → 确定性工具/CSV`，另有 `OpenClaw → 模型 → Skill工具`；尚无两者集成。目标为 `浏览器 → 服务端适配层 → 获准的OpenClaw路由 → Skill工具`，适配层把原答和独立核算**分别**返回；不得给 Agent 偷喂金答案，也不得把核算器伪装成第二个智能体。前后端完整是交互闭环，不要求为了评分拆成 React/FastAPI 两套服务。

以下是**拟议界面合同，非现有 Gateway API，不承诺 endpoint 已存在**：

| 数据组 | 最低字段与含义 |
|---|---|
| 运行身份 | mode（tool/live/replay）、request_id、status、model（实际名称与 local/cloud；工具模式为 null）、duration_ms；取不到耗时写未知，不填0冒充 |
| 输入快照 | user_question、sku、location、weeks；结果与提交时快照绑定，不能跟着新控件值改标题 |
| 来源 | 数据文件版本/哈希、读取时间、证据引用；样本无业务更新时间则写「未知」，不能拿文件读取时间说成库存实时更新 |
| 业务事实 | current_stock、forecast_demand、gap_stock_minus_demand（整数件）、forecast（日期/件）、候选供应商及发货地、unit_cost/shipping_cost（USD/件） |
| 原答与核算 | final_text 原样保存；独立 verification（PASS/FAIL/UNPROVEN 与差异）；正例 total_cost = order_qty × (unit_cost+shipping_cost)，以分计算、误差≤USD 0.01，不使用旧runner的1%宽容；缺证不判 PASS |
| 工具事件与错误 | observed_tool_events：call_id、工具名、参数、结果或脱敏引用、成功/失败、时戳；error：可读原因+可追踪id，不回显密钥、任意服务器路径或完整异常栈 |

适配层必须说明怎样取得**经 owner 选定且已过正负例的显式模型路由**、真实工具事件以及同源数据；本地模型未过关时，实时模式保持未就绪。真实事件缺失时是 `UNPROVEN`，不得用模型文本补造。浏览器不直连模型提供方、不下发 key、不提交任意 SQL/shell/文件路径。结构化工具请求和返回字段应白名单验证；模型输出按不可信文本渲染，禁用原始 HTML/脚本，页面日志和回放导出均脱敏。

## 6. 范围与决定点
